# Diana

Голосовая оболочка Codex на базе готовых компонентов Pipecat.

## Текущее состояние

Первый этап: stdio-подключение к установленному Codex и диагностика сохранённых
тредов. Реальное подключение и `thread/list` проверены на Codex 0.154.0.
Управляющий сокет текущего приложения отсутствует. Доступ к метаданным через
отдельный сервер не доказывает возможность управлять активной задачей в другом
приложении. Возобновление треда, запуск модели и голосовой разговор ещё не проверены.

Клиент маршрутизирует ответы, уведомления, ошибки и таймауты. Пока нет интерфейса
подтверждений, входящие запросы сервера завершаются ошибкой, а не согласием.
Ключи и содержимое переписок в диагностический отчёт не выводятся.

## Короткие проверки

```bash
python3 -m unittest discover -s tests -v
python3 -m diana.probe
```

App Server использует служебную базу в `~/.codex`, поэтому запуск из ограниченной
песочницы может не работать. Проба читает метаданные, не запускает запрос модели.

## Установка голосовых зависимостей — запускает пользователь

```bash
cd /home/zephyr/dev/diana
nix-shell --run 'bash scripts/install-voice.sh'
```

Команда скачивает Nix/Python-зависимости, создаёт `.venv` и `uv.lock`, проверяет
импорт библиотек. Установку и совместимость wheels на NixOS ещё нужно проверить.
Модели Whisper/Piper скачиваются отдельным следующим шагом. Микрофон не включается.
Выбран WeSpeaker без аккаунта Picovoice. Eagle исключён из актуальных зависимостей.
После смены зависимостей нужно повторить установку для обновления `.venv` и `uv.lock`.

## Голосовые зависимости установлены

Проверены импорты: Pipecat 1.7.0, aiortc 1.15.0, ONNX Runtime 1.24.4,
Faster Whisper 1.2.1, Piper 1.8.0, Eagle 2.0.1. `uv.lock` фиксирует разрешённые версии.

Загрузка моделей и сквозная проверка Piper → WAV → Whisper (запускает пользователь):

```bash
nix-shell --run 'bash scripts/prepare-models.sh'
```

Скачиваются многоязычный Whisper small, русский Piper `ru_RU-irina-medium`
и WeSpeaker ResNet34 ONNX из официального репозитория `Wespeaker` на Hugging Face.
Ссылка закреплена на конкретную ревизию, загрузка проверяется по SHA256 из метаданных
Hugging Face. Старый источник `wenet.org.cn` заменён после ошибки просроченного
TLS-сертификата. Проверка сертификатов остаётся включённой.
Для WeSpeaker используются ONNX Runtime и эталонные признаки torchaudio/Kaldi;
обучение модели не проводится. Torch/torchaudio устанавливаются из CPU-индекса.
`speaker-model-check.json` фиксирует источник, SHA256 и результат запуска модели.
Синтетическая фраза проверяет только выполнение модели и не становится профилем владельца.
Если Whisper/Piper уже прошли проверку, продолжить только с WeSpeaker:

```bash
nix-shell --run 'uv run --no-sync python -m diana.models --speaker-only'
```

Whisper работает на CPU в int8, четыре потока. Результат — `.local/models-check.json`,
синтезированная проба — `.local/voice-sample.wav`. Это проверка загрузки и выполнения,
не измерение точности на реальном микрофоне. Повторная проверка без скачивания:

```bash
nix-shell --run 'uv run --no-sync python -m diana.models --check-only'
```

Диагностика микрофона на готовом клиенте Pipecat:

```bash
nix-shell --run 'uv run --no-sync python -m diana.microphone --host 127.0.0.1 --port 7860 -t webrtc'
```

Открыть `http://127.0.0.1:7860/client/`, подключиться и разрешить микрофон.
Уровень звука выводится в терминале. Аудио не сохраняется и не отправляется в Codex.
Сервер и HTTP-страница проверены; браузерный микрофон требует проверки пользователем.
Полноценного разговора и фильтра владельца в этом диагностическом режиме ещё нет.

## Регистрация владельца

```bash
nix-shell --run 'uv run --no-sync python -m diana.owner --mode enroll --host 127.0.0.1 --port 7861 -t webrtc'
```

Открыть `http://127.0.0.1:7861/client/`, нажать Connect, разрешить микрофон.
Говорить одному в тихой комнате фразами по 3–4 секунды или дольше.
Прогресс `1/6` … `6/6`, уровень микрофона и подсказки показываются на странице
через штатные сообщения Pipecat и дублируются в терминале. Если аудио не поступает
пять секунд, появляется подсказка проверить микрофон/Mute. Короткие перерывы
в речи сохраняют накопленный фрагмент; пауза от 0.8 секунды его сбрасывает.
После шести фрагментов по две
секунды речи профиль сохранится в `.local/owner.json` с правами 0600.
Аудио остаётся только в оперативной памяти. Существующий профиль не перезаписывается.

После сообщения об успешном сохранении отключить микрофон и остановить сервер
через Ctrl+C. Проверка профиля:

```bash
nix-shell --run 'uv run --no-sync python -m diana.owner --mode verify --host 127.0.0.1 --port 7861 -t webrtc'
```

На той же странице снова подключить микрофон. Сравнить значения сходства для своей
речи и речи другого человека. Значение — косинусное сходство, не вероятность.
Универсального порога авторизации пока нет: это диагностика для калибровки.
Вычисление показывается отдельно от двух секунд сбора речи. Этот режим не
отправляет команды Codex и не обещает мгновенного перебивания.
При регистрации отбрасываются фрагменты со сходством к накопленному профилю ниже
0.45: это предварительная проверка согласованности, не проверенный порог доступа.

Проверены девять тестов и локальная цепочка VAD/WeSpeaker на синтетическом WAV.
Браузерный микрофон и качество различения людей ещё требуют ручной проверки.

## Распознавание речи владельца

```bash
nix-shell --run 'uv run --no-sync python -m diana.owner --mode transcribe --host 127.0.0.1 --port 7863 -t webrtc'
```

Открыть `http://127.0.0.1:7863/client/`, Connect, сказать фразу и сделать паузу.
На странице появляется распознанная реплика пользователя. Пауза около 0.8 секунды
завершает реплику. Короткий начальный буфер сохраняет начало слов для Whisper.
Для проверки личности нужна минимум секунда обнаруженной речи. После 20 секунд
реплика обрезается с явным сообщением; продолжение игнорируется до паузы.

Порог 0.35 предварительный: исходная выборка владельца 0.493–0.668, чужой записи
0.067–0.132. Длинная реплика проверяется перекрывающимися окнами, включая хвост;
любое окно ниже порога отклоняет всю реплику до запуска Whisper. Это вероятностная
проверка: смешанная речь и новые голоса пока не валидированы. Никаких команд Codex
этот режим не запускает. Аудио обрабатывается локально в ограниченной очереди;
профиль не изменяется, записи на диск не пишутся.

Проверены 21 тест и реальная цепочка WeSpeaker → Whisper с синтетическим профилем
только в памяти. Скрипт `scripts/check-transcription.py` не меняет профиль владельца.
Браузерное распознавание реального владельца пока требует проверки.

# Голосовой диалог

Запуск на том же адресе `http://127.0.0.1:7863/client/`:

```sh
nix-shell --run 'uv run --no-sync python -m diana.owner --mode chat --host 127.0.0.1 --port 7863 -t webrtc'
```

Нажать Connect, сказать фразу и сделать паузу. WeSpeaker проверяет владельца,
Whisper распознаёт речь локально, текст отправляется в Codex через установленный
app-server, ответ показывается на странице и озвучивается локальным Piper.
Используется текущая авторизация Codex. Это отдельный разговор, его ID сохраняется
в `.local/conversation-id`; история хранится самим Codex. Аудио не сохраняется.

Новая прошедшая проверку и распознанная реплика отменяет предыдущий ответ Codex
и очищает очередь озвучки. Это перебивание после конца фразы, не мгновенное
перебивание по началу речи. Слишком короткие реплики пока не проходят проверку.
Для комфортного первого теста лучше использовать наушники.

Текущий этап — разговор: инструкция запрещает выполнение действий, файловая
песочница read-only; запросы подтверждения клиент отклоняет. Это не изолированный
чат без инструментов: используются настройки установленного Codex. Управление
проектами голосом и интерфейс подтверждений ещё не подключены.

Проверки: `python -m unittest discover -s tests -v`; `python scripts/check-dialogue.py`
делает один реальный запрос в отдельный тестовый диалог, проверяет resume и Piper.
Протокол: [официальная документация OpenAI](https://learn.chatgpt.com/docs/app-server),
схемы сверены с установленным `codex app-server generate-json-schema`.
