## Что работает сейчас

1. Браузер получает микрофон и соединяется с Python-сервером через Pipecat/WebRTC.
2. Silero VAD выделяет речь; после паузы собирается законченная реплика.
3. Проверка владельца WeSpeaker опциональна и **выключена по умолчанию**.
4. Локальный Whisper small распознаёт русский текст на CPU.
5. Текст передаётся установленному Codex через `codex app-server --stdio`.
6. Ответ показывается в браузере и озвучивается **Piper, голос Ирина**.
7. Диалог Codex сохраняет контекст после переподключения.

Пользователь подтвердил, что распознавание и голосовые ответы работают.
Изначально проверка владельца пропускала его речь и отклоняла речь из аниме.
Позже пользователь явно попросил временно отключить её — это сознательная настройка,
не неисправность. Теперь при выключенном фильтре принимается речь любого человека.

## Как открыть и запустить

- Рабочая папка: `/home/zephyr/dev/diana`.
- ОС: NixOS. Python-зависимости находятся в `.venv`, окружение — `shell.nix`.
- Основной пульт: **http://127.0.0.1:7863/**.
- Сохранённый стандартный клиент Pipecat: **http://127.0.0.1:7863/client/**.
- Кнопка «Подключить», затем обычная речь с паузами.
- Одновременно подключать только одну страницу к этому серверу.

```sh
cd /home/zephyr/dev/diana
nix-shell --run 'uv run --no-sync python -m diana.owner --mode chat --tts piper --host 127.0.0.1 --port 7863 -t webrtc'
```

Последний рабочий запуск был с этими параметрами. Не предполагать, что процесс
пережил завершение сессии или перезагрузку ноутбука: при необходимости проверить порт.
Автозапуск системной службой не настраивали. Не менять порт без необходимости:
раньше несколько диагностических адресов путали пользователя.

## Решения, которые важно сохранить

### Озвучка

- **Piper выбран по умолчанию ради скорости**, несмотря на более низкое качество.
- Голос: `ru_RU-irina-medium`, локальный ONNX.
- Подключён также `edge-tts`, голос `ru-RU-SvetlanaNeural`.
  Пользователю понравилось качество Светланы, но не задержка; он попросил вернуть Piper.
- Светлана остаётся доступна через `--tts edge`. Браузер Edge и API-ключ не нужны.
  Текст ответа при этом отправляется Microsoft.
- При ошибке Edge или тайм-ауте 15 с происходит возврат к Piper;
  следующая попытка Edge разрешается через минуту. Причина показывается в пульте.
- МиниMax обсуждали, но **не подключали**. Обсуждение API не является поручением
  подключать платный сервис или менять текущий голос.

### Проверка владельца

- Выбран WeSpeaker, а не Eagle/Picovoice: пользователь не хотел аккаунт Picovoice.
- Профиль уже зарегистрирован: `.local/owner.json`, нормализованный вектор 256 измерений,
  права 0600. **Не перерегистрировать и не перезаписывать без запроса пользователя.**
- Регистрация собирала шесть фрагментов по две секунды речи. Исходные записи не сохранялись.
- В настройках пульта есть «Проверять мой голос». Сервер подтверждает изменение;
  оно применяется к следующей обрабатываемой реплике.
- При каждом новом подключении chat/transcribe проверка снова выключена.
- При выключенной проверке не вызывается encoder WeSpeaker, не применяется ограничение
  минимум одной секунды для идентификации; VAD и Whisper продолжают работать.
- При включённой проверке предварительный порог — 0.35. Наблюдали сходство владельца
  0.493–0.668, чужой записи 0.067–0.132. Это небольшая выборка, не гарантия идентификации.
- Длинные реплики проверяются перекрывающимися окнами, включая хвост;
  провал любого окна отклоняет реплику до Whisper/Codex.
- Сходство не является вероятностью. Одновременная речь нескольких людей не валидирована.

### Диалог и действия

- Это отдельный разговор Дианы, **не управление текущим GUI-чатом другого приложения**.
- Авторизация используется из установленного Codex; ключи не копируются.
- ID рабочего диалога: `.local/conversation-id`; история хранится самим Codex.
- `--conversation-state .local/other-thread` позволяет использовать отдельный тестовый диалог.
- Текущий этап — обсуждение вопросов. Инструкция запрещает выполнение действий;
  файловая песочница read-only, входящие запросы подтверждения клиент отклоняет.
- Это не технически изолированный чат без инструментов: настройки установленного Codex
  продолжают действовать. Интерфейса разрешений и исполнения голосовых команд нет.

## Личный пульт

Пользователь выбрал «разговор + состояние»: светлый спокойный интерфейс без большого
бокового меню. HTML/CSS/JavaScript, готовые Pipecat Client JS + SmallWebRTC, сборка esbuild.
Никакого нового UI-фреймворка или CDN в рабочем клиенте.

Сделано:

- переписка, подключение/отключение, выключение микрофона;
- ручной ввод текста; он явно помечается как ввод без проверки голоса;
- кнопка остановки ответа;
- уровень PCM микрофона, результат проверки и явный статус отключённого фильтра;
- состояние обработки и реальные длительности этапов;
- карточка реплики с причиной решения, временной шкалой и ID диалога;
- JSON-экспорт выбранной трассировки по кнопке;
- выбор микрофона и динамиков, если браузер поддерживает `setSinkId`;
- мобильная раскладка;
- стандартная `/client/` оставлена для независимой диагностики.

История экрана живёт в текущей вкладке: до 100 трассировок и 200 сообщений.
После обновления страницы экран пустой, но контекст Codex сохраняется.

### Что означают замеры

Длительности вычисляются монотонными часами сервера. «До отправки звука» — от
последнего состояния речи VAD до первого аудио в выходном тракте; для клавиатуры —
от приёма текста сервером. Это **не измерение точного момента звука в динамиках**.
WebRTC, браузер и устройство добавляют задержку. «Первое аудио» включает синтез,
загрузку и декодирование первого предложения. Пропущенные этапы показаны прочерком.
Причины в интерфейсе — факты программы, не внутренние рассуждения модели.

Один реальный браузерный тест со Светланой показал около 6.3 с до аудио:
примерно 5 с Codex и 1.3 с озвучка. Это единичный пример, не стабильный бенчмарк.
Задержка остаётся известной проблемой; пользователь отложил её оптимизацию.

## Известные ограничения

- Перебивание голосом срабатывает после завершения, проверки (если включена)
  и распознавания новой фразы, а не по первому звуку.
- Кнопка «Стоп» отменяет текущий ответ и очищает очередь озвучки.
  Учтена остановка до получения ID нового turn от Codex.
- Пауза завершения — 0.8 с после состояния речи VAD; поведение VAD добавляет своё время.
- Реплика ограничена 20 секундами: обрабатывается начало, хвост игнорируется до паузы,
  обрезка обозначается в трассировке. Очередь ограничена двумя репликами.
- Сначала ждём ответ Codex, затем синтезируем и воспроизводим по предложениям.
  Мгновенной потоковой озвучки токенов нет.
- Для разговоров удобны наушники, особенно при отключённой проверке владельца.
- Сервис предназначен для localhost, не для внешней публикации.

## Зависимости и локальные данные

Pipecat 1.7.0, aiortc, ONNX Runtime, faster-whisper, Piper, torch/torchaudio 2.8.0 CPU,
edge-tts. Версии закреплены в `uv.lock`, браузерные зависимости — в `package-lock.json`.
Whisper small работает в int8 на CPU, четыре потока.

WeSpeaker ResNet34 ONNX скачан из официального Hugging Face:

- ревизия `ff1ac5bca8ef11e90662b879aa923979e0bd277b`;
- SHA256 `9fea6516d7ad6bf0a76c7689f5a49b65d330fad6dde96c91bb4435ffbfe056a1`.

Старый источник wenet.org.cn был заменён после ошибки просроченного сертификата.
Проверку TLS не отключали. Синтетические пробы не записываются как профиль владельца.

`.local/`, `.venv/`, `node_modules/`, `web/dist/`, `.env` исключены из Git.
Сырые записи разговора не сохраняются. Экспорт трассировки содержит текст реплики
и ответа, поэтому его не следует добавлять в репозиторий автоматически.

После получения репозитория на новой машине нужна сборка пульта:

```sh
npm ci
npm run build
```

## Как работать с пользователем дальше

- Пользователь хочет, чтобы агент сам выполнял доступные действия и проверял результат.
- Крупные установки/скачивания и длинные терминальные команды предпочитает запускать сам;
  небольшие команды агент выполняет самостоятельно.

- Давать конкретный адрес и действие в интерфейсе, не заставлять разбираться в логах.
- Текущий этап завершён. Ждать нового задания.
